### day_idx 계산 경로 ← **근본 문제**

`master_pipeline.py:656-670`:


### REAR-only 증상 원인 확정

| 항목 | 값 | 비고 |
|------|-----|------|
| 일반 배치 폴더 수 | 1개 | 매일 1 폴더 처리 |
| folder_idx | 0 | enumerate 고정 |
| day_idx | 0 | = folder_idx |
| COMBO[0 % 9] | ("rear", 1) | REAR V1 고정 |
| 실제 로그 (2026-04-16) | file_idx=0/100/200/201 모두 동일 세션 | 동일 day_idx=0 |

**결론**: 코드에 rear 하드코딩은 없으나, `day_idx = folder_idx` 구조로 인해 1폴더 실행에서는 COMBO[0] = REAR V1이 항상 선택됨. 9일 로테이션은 동일 배치에 9개 폴더가 있어야만 의미를 가짐.

### track_title 전달 체인

```
master_pipeline.py:824-830
  build_and_adapt_yacha(video_type="single", track_name=track_title, ...)
    └─ thumbnail_adapter.py → build_yacha_thumbnail_set(track_name=track_title, ...)
         └─ thumbnail_service.py → _build_variant_*_raw(...)
              └─ _apply_text_overlay(raw_path, final_path, variant, video_type)
                   ← track_name 파라미터 없음 — 전달 체인 단절
```

`track_name`은 `build_and_adapt_yacha()`까지 도달하나, `_apply_text_overlay()`에 track_name 파라미터 없음.

### 3CROW와 비교

3CROW: `_crow_add_text_overlay()` — `mood_word`를 동적으로 생성 (장르/purpose 기반), PLAYLIST 하드코딩 없음.  
YACHA: `_apply_text_overlay()` — `line1 = "PLAYLIST"` 고정. 비대칭 구조.

### 현황

- **Playlist 영상**: "PLAYLIST" 오버레이 = 정확 ✅
- **Single 영상**: "PLAYLIST" 오버레이 = **잘못됨 ❌** (track 제목 또는 "SINGLE" 이어야 함)
- **Shorts 영상**: "PLAYLIST" 오버레이 = **잘못됨 ❌** ("SHORTS" 또는 트랙명 이어야 함)

### 수정 방향 (참고)

```python
# thumbnail_service.py _apply_text_overlay 수정안
def _apply_text_overlay(raw_path, final_path, variant, video_type, track_name=None):
    if video_type == "playlist":
        line1 = "PLAYLIST"
    elif video_type == "single":
        line1 = track_name.upper()[:12] if track_name else "SINGLE"
    elif video_type == "shorts":
        line1 = track_name.upper()[:12] if track_name else "SHORTS"
    else:
        line1 = "PLAYLIST"
```
